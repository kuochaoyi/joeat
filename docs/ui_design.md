# 介面設計原則

2026-11 依使用者回饋「文字太多、難以閱讀」,參考 Google Stitch 原型(`stitch_joeat_group_dining_prototype.zip`,色彩與元件規範見其中的 `DESIGN.md`)改版。**只借版面與互動手法,不借文案**:原型裡的「100% 安全」「7/7 安全」、Google 評價與價格,都違反本專案的設計原則,沒有採用。

## 手法

| 原則 | 怎麼做 |
|---|---|
| 一個畫面一個重點 | 每頁一個標題、一句灰字、底部固定一個主按鈕 |
| 卡片只放「圖示 + 短標題 + 一行小字」 | 步驟列(`StepRow`)、料理圖示卡(`.pick`) |
| 說明收起來,不刪掉 | `Hint`(「ⓘ 說明」,預設收合);結果卡片的「查看原因」 |
| 狀態用顏色,不用句子 | 綠 / 琥珀 / 紅 / 灰的狀態列與膠囊(`.status`、`.badge`) |
| 選項用膠囊與分段控制 | `Chip`、`Seg`、人數加減、預算拉桿 |
| 進度用圖形 | `Meter`(橘色進度條) |

色彩:品牌橘 `#FF6B35`、LINE 綠 `#06C755`(只用在分享)、狀態綠 / 琥珀 / 紅,背景 `#F8F9FA`。元件在 `frontend/app/globals.css` 與 `frontend/components/ui.tsx`。

## 不能因為「簡潔」而藏起來的東西(安全規則)

- **資料不足、重要警示永遠留在卡片表面**:狀態列直接寫「資料不足:花生（重要）、牛肉」,摺疊的只有理由、分數、地址、回報。
- **沒有任何「安全」字樣**:綠色狀態只寫「已知資料沒有衝突」。
- 店家聲明在卡片上是「店家聲明・已驗證:花生」膠囊,完整的帶日期句子在「查看原因」裡。
- 免責聲明保留在結果頁底部(小字,不收合)。
- 寵物 / 小孩的狀態在卡片上是短膠囊(「資訊不足」「可以」…),完整句子在詳情裡。
