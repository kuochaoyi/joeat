# 使用者測試回饋與處理狀態

來源:2026-11 對 **Google Stitch 原型**(`stitch_joeat_group_dining_prototype.zip`,13 步 LINE bot + LIFF 假資料流程)的測試。回饋是對原型的觀察,所以先要分清楚「原型有、我們沒有」與「原型和我們一樣」。

## 原型和我們設計原則衝突的地方(**沒有**照原型做)

| 原型 | 我們 | 為什麼 |
|---|---|---|
| 「100% 安全」「7/7 安全」「完全沒有(很安全)」 | 禁止這類用語 | 系統不能承諾安全(決策紀錄 D2,有測試守住) |
| 預算當**硬限制**(「只挑所有人預算交集內的餐廳」) | 預算只是軟條件,不排除、不計分 | 我們沒有價格資料 |
| Google 評價 4.6★、價格 $350–450、「142 間店」 | 評價與價格顯示「—」 | 沒有可靠來源;不能假裝有 |
| 餐後回饋「立刻降級店家標籤」 | 回報不會自動生效,審核者查證後才暫停聲明 | 防止被濫用去打掉競爭對手的聲明 |

## 回饋清單

| # | 回饋 | 狀態 | 做法 |
|---|---|---|---|
| 老師 1 | 攜伴(寵物、小孩) | **已做(沒有資料)** | 主揪建立時勾「有人帶寵物 / 小孩」(之後可改)。寵物:店家明確不讓才排除;小孩:只警示。資料靠店家填寫頁新增的兩題,**目前沒有任何餐廳有資料,所以現在全部顯示「資訊不足」** |
| 老師 2 | 最後投票用拉桿,不一定三選一 | **已做** | 每位成員對 Top 3 每間拉 0–10 或「都可以」;匿名;同分取「沒人討厭」者。API.md「最後投票」 |
| 老師 3 | 飲食 MBTI | **已做(趣味 + 偏好捷徑)** | 9 題、3 條軸線(嘗鮮↔熟悉、濃郁↔清爽、願意走↔想近)、8 種類型,例如「🧭 美食探險家」。結果依類型**建議**幾種料理,讓使用者在偏好頁確認後才存;聚餐頁只顯示團隊組成人數(至少 2 人才顯示)。**不影響推薦與排名** |
| 老師 4 | 資料來源要不要買 | **建議先不買** | 買得到存在性、營業時間、價格、評價;買不到過敏原與共用設備,那正是店家聲明的價值。試辦後看缺口 |
| 老師 5 | 附近 vs 外地(當地特產) | **未做** | 目前只有鹽埕區資料。地圖選點在範圍外時會警告 |
| 2 | 時間由大家選,主揪只決定投票時限 | **已做** | 建立時選「大家投票決定」:主揪挑日期 × 時段與截止時間,成員勾選自己可以的;可以的人最多的勝出 |
| 3 | 地圖選點 | **已做** | Leaflet + OpenStreetMap 圖磚;可點地圖或用我的位置;範圍外警告 |
| 6 | 人數上限更多 | **已做** | 2–20(API、資料庫、bot、前端) |
| 7 | 分享連結(可能沒有群組) | **已做** | 明確的「複製連結」「分享到 LINE」「用手機分享」 |
| 8 | 建立後跳到哪、主揪不確定自己填完沒 | **已做** | 建立後直接進「填限制」;聚餐頁明確標「✅ 已填寫(可修改)」 |
| 9 | 過敏原 / 宗教問法 | **已做** | 逐題問「你是否有以下過敏原?」每題有明確的「沒有」,全部回答才能存;宗教規範獨立一題(不吃牛 / 豬(宗教)、清真…),原因為宗教時被視為更嚴格的安全型限制;找不到自己的過敏原有說明 |
| 11、12 | 預算太低、預算用拉桿 | **已做(軟條件)** | 100–1500 以上的拉桿,選填。**畫面明說不會排除任何餐廳、目前沒有價格資料**。不是原型的硬限制 |
| 13 | 要有歐式料理;偏好只勾選、預設都可 | **已做** | 新增「歐式」(義式是它的子類,選歐式也會匹配義式店);偏好改成只勾想吃的,沒勾 = 都可以 |
| 14 | 不能修改已填答案 | **已做** | 限制與偏好頁重新打開會帶出已存的內容,按鈕變「更新」;新增 `GET /participants/{id}/answers` |

清單的編號 1、4、5、10 沒有出現在回饋裡(不確定是沒有還是漏貼)。

## 第二輪:「文字太多、難以閱讀」(UI 改版)

依另一份 Stitch 原型的版面手法改版,原則與取捨見 [ui_design.md](ui_design.md):每頁一個重點、卡片只放圖示加短標題、說明收進「ⓘ」、狀態用顏色膠囊、主按鈕固定在底部。結果卡片從「分數列 + 警示列表 + 推薦理由 + 地址」縮成「名稱 + 一行狀態 + 最重要的警示 + 查看原因」。**資料不足與重要警示不會被收起來。**

## 已知限制

- **店家填寫頁與審核後台沒有縮短內容**:只換了色彩與按鈕。店家 19 題都必須回答,文字量主要來自題目本身。

- **攜伴目前等於「提醒你去問店家」**:沒有任何餐廳的寵物 / 小孩資料,要等店家填寫並經審核才有內容。
- 「寵物」不分種類與體型,只問「室內座位可不可以帶」(只有戶外座位可以請店家寫在備註)。
- 攜伴只在網頁設定,LINE bot 沒有對應指令。
- **飲食類型不影響推薦**:這是刻意的(決策:先不讓它進引擎,因為沒有真實資料可以訂權重)。「願意走 / 想近」軸線目前只是描述,不改任何距離計分。類型的名字、題目與料理對應是我訂的,**沒有任何心理測量或使用者資料的依據**,只是好玩的分類。
- **預算拉桿目前不影響推薦**(沒有價格資料),只是記錄。
- **「大家選時間」只比較人數**,不考慮誰必須到;沒有人勾選時沒有結果。
- **投票統計在人少時可能被推測**(例如 2 人時,總分幾乎洩漏另一人的票)。
- **偏好改成只有「想吃」後,不再能表達「不太想」**(引擎仍支援,UI 不再提供;舊聚餐裡已存的「不太想」在編輯時會被丟掉)。
- 地圖圖磚來自 OpenStreetMap 公開伺服器,僅適合試辦流量;正式上線需要自己的圖磚服務或付費方案。
- 投票與時間票選**只在網頁**,LINE bot 沒有對應指令。
- 沒有前端自動化測試;手機版面只用視窗模擬量過。
