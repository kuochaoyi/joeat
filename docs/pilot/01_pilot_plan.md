# 店家聲明試辦計畫(建議版,可改)

> 狀態:**草案**。目標、規模、停止條件都是我依決策紀錄([0001](../decisions/0001-merchant-declaration.md))提的建議,請你改成你真的接受的版本。
> 先讀 [05_go_live_checklist.md](05_go_live_checklist.md):**目前有 6 個阻擋項(見 `pilot_preflight.py`),在它們解掉之前不要把連結交給任何真實店家。**

## 1. 試辦要回答什麼

試辦不是要「上線」,是要用很小的規模回答下面五個問題。**答案可以是「不行」**,那也是有價值的結果。

| # | 問題 | 為什麼重要 | 怎麼看 |
|---|---|---|---|
| H1 | 能不能在 10 分鐘內,用電話回撥確認一位店家的身分? | 驗證人力是整個模式的成本(決策紀錄「仍待你決定」第 3 項) | 你自己記錄每通電話的分鐘數;`pilot_metrics.py` 的「邀請 → 驗證完成」 |
| H2 | 店家對關鍵過敏原,共用設備會答「確認沒有共用」,還是多半答「不確定 / 可能」? | **決定過敏族群能不能真的得到「已確認」**。多數答不確定 → 這個功能對過敏者價值有限(決策紀錄 D4 的後果) | `pilot_metrics.py` 的「共用設備怎麼答」 |
| H3 | 店家自己能填完嗎?多久?卡在哪? | 表單 19 題、手機上填(預期 5–10 分鐘,**沒有實測過**) | 送出率、你在旁邊觀察 / 事後問 |
| H4 | 店家的答案和我們原本的第三方資料(部落格、媒體)常常不一致嗎? | 不一致 = 聲明有價值,也 = 審核最花力氣的地方 | 「取代第三方證據」次數、審核者的主觀感受 |
| H5 | 店家覺得這是「風險資訊來源」還是「行銷工具」?願意配合更新嗎? | 設計原則 D6:不是行銷工具。如果店家期待曝光,關係會走偏 | 通話紀錄裡店家的原話;90 天後是否願意續期 |

## 2. 規模與節奏

- **第一波 6 家**(名單與理由:[02_candidates.md](02_candidates.md)),**約兩週**。決策 D7:少量、人工審核、強可信度,不追求大量。
- 第一波結束後**停下來看數字再決定**第二波(最多再 6 家)。不要在看完 H1–H5 之前擴大。
- 不收費、不承諾曝光、不承諾排名(D5:聲明**不影響推薦分數**——對店家要誠實說這點,見通話腳本)。

| 時間 | 做什麼 | 誰 |
|---|---|---|
| 第 0 週 | 解掉阻擋項:法務、架站(https)、換金鑰、乾淨資料庫、備份。`pilot_preflight.py` 全綠 | 你 +(法務 / 架站協助) |
| 第 1 週 | 打電話給第一波 6 家(營業時間以外的空檔)。同意的當場建立認領、驗證、傳連結 | 你(營運) |
| 第 1–2 週 | 店家填寫 → 你審核 → 發布 → 回報店家結果。每天看一次 `/ops` 佇列 | 你 |
| 第 2 週末 | `pilot_metrics.py`、逐家回顧、寫結論(H1–H5 各一段) | 你 + 我可以協助整理 |

## 3. 停止條件(先寫好,免得當下捨不得停)

**立刻停止整個試辦、全部聲明撤下**(`/ops/declarations/{id}` →「撤下」):

- 有使用者回報因為聲明內容發生過敏反應 / 身體不適(先在「事故」登錄,系統會立刻暫停該店的正向聲明);
- 收到店家或第三方的法律主張、或你對切結文字的責任有疑慮;
- 發現資料被錯誤發布且無法在一天內處理。

**暫停第二波**(第一波繼續做完):

- 6 家裡**少於 3 家**完成填寫並通過審核;
- 平均一家的營運時間(打電話 + 審核)超過你願意長期負擔的量(先決定這個數字,例如 90 分鐘 / 家);
- H2 的結果是「幾乎沒有人答確認沒有共用」——此時要先討論怎麼調整,不是找更多店。

## 4. 你每家要記錄的(最少)

用試算表即可(範本:[03b_pilot_log_template.csv](03b_pilot_log_template.csv))。**不要記老闆的姓名或個人電話**——只記職稱;正式資料庫也不存自然人姓名(這是既有的設計原則)。

聯絡日期、管道、結果(同意 / 拒絕 / 之後再說 / 打不通)、通話分鐘數、對方職稱、驗證方式、傳連結的日期、填寫完成日期、審核結果、與原資料不一致的項目、店家原話(重要的疑慮或期待)、後續待辦(到期日)。

## 5. 風險,以及目前怎麼處理

| 風險 | 目前的處理 | 還欠什麼 |
|---|---|---|
| 切結文字有法律責任(過敏者依聲明決定用餐) | 用語只陳述事實與日期、不說「安全」(D2,有測試);預檢程式把「法務未核准」列為阻擋項 | **律師審閱並核准文字**(只有你能做) |
| 店家答錯 / 菜單改了沒更新 | 聲明 90 天到期;共用設備不確定會降級;可立即撤下(`/ops` 詳情頁);使用者可回報,審核者可升級為事故暫停聲明 | 到期提醒是**手動**(日曆提醒);沒有自動通知 |
| 有人惡意回報要打掉對手的聲明 | 回報不會自動生效,只有審核者升級才暫停;有限流 | 限流擋不住有心人(參與者容易建立) |
| 老闆的手機號碼被當成商用電話打擾 | 候選名單標出手機號碼;腳本規定只在營業時間打、拒絕就不再打 | 你要遵守 |
| 營運人員只有你一人,審核太慢 | 腳本裡不承諾審核時限 | 要不要找第二位審核者(`/ops` 現在是一把共用金鑰) |
| 店家把連結轉傳 | 連結是專屬憑證(192 位元亂數、資料庫只存雜湊)、30 天有效;可「撤銷」 | 轉傳無法技術上阻止;腳本請店家勿轉傳 |
