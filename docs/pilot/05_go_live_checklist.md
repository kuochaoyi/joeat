# 上線前檢查清單(給真實店家的連結寄出之前)

用 `python scripts/pilot_preflight.py`(在**店家實際會用的環境**、用那個環境的真實環境變數執行)檢查。退出碼 1 = 有阻擋項。
**目前在開發環境執行的結果是 6 個阻擋項**——這是對的,因為開發環境本來就不該給真店家。下面逐項說明每一個該怎麼解,以及哪些**只有你能做**。

## 阻擋項(預檢程式會擋)

| # | 項目 | 怎麼解 | 誰 |
|---|---|---|---|
| 1 | **切結文字未經法務審閱** | 找律師審閱 `app/core/merchant_form.py` 的 `ATTESTATION_TEXT` 與店家頁的用語(尤其:「聲明」的責任歸屬、對用餐者的免責聲明)。核准後改 `ATTESTATION_TEXT` / `ATTESTATION_VERSION`(如 `attest-v1`)與 `LEGAL_REVIEW = {"status": "approved", ...}`,並刪掉 `tests/unit/test_preflight.py::test_the_draft_attestation_text_is_always_a_blocker`(它的用途是確保程式碼庫出貨時「預設是未核准」,核准後它就不再成立)。**沒核准前,店家頁頂端會顯示「不可正式上線」橫幅** | **你**(法務);改檔案我可以協助 |
| 2 | **前端網址是 localhost / 不是 https** | 把前端與後端部署到有 **https** 的公開網址。設定:後端 `FRONTEND_URL`(前端網址)、`CORS_ORIGINS`(包含前端網址);前端 **build 時**設 `NEXT_PUBLIC_API_BASE`(後端 https 網址,**寫進打包檔,改了要重 build**)。連結裡的 token 走標頭不走網址,但頁面與 API 都必須是 https | **你**(主機 / 網域)。`docker-compose.yml` 寫了但**從沒執行過** |
| 3 | `OPS_API_KEY` 空或太弱 | `python -c "import secrets; print(secrets.token_urlsafe(24))"` 產生,設進後端環境變數。**這是 `/ops` 唯一的防護** | 你 |
| 4 | `ID_HASH_SECRET` 是開發預設 | 同上產生並**保存好**(換掉會讓既有的雜湊失效) | 你 |
| 5 | `ALLOW_TEST_EVIDENCE=true` | 試辦環境必須是 `false`(示範資料會被當真實資訊顯示) | 你 |
| 6 | 資料庫裡有示範資料 | 試辦用**全新資料庫**:`python scripts/seed.py --reset --no-fixtures`,**不要**執行 `seed_demo_merchants.py`。`--no-fixtures` 會移除種子裡 3 筆隱藏的假證據,真實的第三方證據保留 | 你(我可以協助) |

## 強烈建議(預檢不會擋,但我會在寄出連結前做)

- [ ] **用真的手機走一遍完整流程**:在試辦用的 https 網址上,自己扮演店家(用你自己的手機、LINE 內建瀏覽器與 Safari / Chrome 各一次),跑 邀請 → 驗證 → 填寫 → 送出 → 審核 → 發布 → 撤下。**用另一個資料庫排練**,排練資料別留在試辦資料庫(那裡只能有真實店家)。
- [ ] **每天備份**:`pg_dump` 排程 + 實際還原測試一次。聲明不能刪除,備份是唯一的後悔藥。
- [ ] **`/ops` 加一道網路層防護**:反向代理限制來源 IP 或放在 VPN / Basic Auth 後面。`/ops` 沒有登入失敗鎖定,單靠金鑰。
- [ ] **店家 API 限流**:`/merchant/*` 沒有速率限制。token 是 192 位元亂數、不可能猜中,但仍可被灌流量;在反向代理加限流。
- [ ] 有第二個人讀過 [04_operator_runbook.md](04_operator_runbook.md),萬一你不在,他知道怎麼撤下與處理事故。
- [ ] 用的是真正的 PostgreSQL(只在 16.2 測過;開發用的內嵌版 `pgserver` 不是給試辦用的)。

## 已知缺口(試辦期間會遇到,先知道)

- **到期提醒是手動的**:系統不會通知任何人聲明快到期;聲明到期後該店對該屬性自動回到「資訊不足」。
- **沒有任何自動通知**:新送出的聲明不會通知你,要自己看 `/ops`。
- **手機版面只用 375px 視窗模擬測過**,沒測真機、沒測 LINE 內建瀏覽器;答案按鈕與勾選框已放大到好點的尺寸。
- 附件(菜單照片 / 認證檔)上傳沒做,只收菜單連結。
- 宗教 / 醫療原因的選項 UI 沒做;LINE bot 沒有回報與嚴格模式的指令。
- 所有流程**只用假資料跑過**,沒有任何真實店家使用過。第一批店家會碰到我們沒想到的事——這就是試辦的意義。
